# Agent contributor rules
Operate only inside this repository. Never inspect or modify unrelated repositories, services, databases, containers or customer workloads. Maintain SPRINTS.md and BACKLOG.md for scope changes. Add an issue for new features, and attach each PR to an active-sprint issue or backlog item (break/fix exempt). Validate tests and docs before opening PRs. Prefer standard-library or license-audited open source. Do not store secrets in Git, contact prospects, provision cloud resources, or pay for APIs. Never merge unreviewed changes. Leave running containers and persistent volumes intact unless owned by this project. Include PR URL and test evidence in progress updates.

## README badge convention

The source of truth is [madmallard-repository-standards](https://github.com/drakeg/madmallard-repository-standards), when it publishes actionable standards; this local policy applies until then. Maintain a compact Shields.io badge group immediately beneath the root README title, preferably two or three rows. Inspect actual manifests, dependency lockfiles, Dockerfiles, deployment configuration, LICENSE, releases, and GitHub Actions before changing a badge. Never invent technologies, versions, workflow success, security checks, deployments or releases. Version badges require verified configuration; CI, release, license and repository-statistic badges must be dynamic. Include release, security, or deployment badges only when the corresponding capability exists. Make badges link to verified configuration or relevant pages. Preserve all existing README content outside the badges. Run `python3 scripts/validate_badges.py` with normal documentation checks and update the validator when documented badge conventions change.
